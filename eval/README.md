# Эталон

Эталон — ручная разметка диалогов по чек-листу. С ним сравниваются оценки модели: так видно, где модель ошибается, по каким критериям и на каких языках.

## Где лежат файлы

| Файл | Что в нём | В git |
|---|---|---|
| `eval/compare.py` | Код сравнения | да |
| `backend/tests/eval/test_compare.py` | Тесты на синтетических данных | да |
| `data/gold/gold.json` | Ручная разметка | **нет** |
| `data/gold/model.json` | Выгрузка оценок модели | **нет** |
| `data/gold/report.json` | Отчёт сравнения | **нет** |

Разметка и выгрузки содержат id диалогов DEV, а отчёт — выводы по ним. Репозиторий публичный, поэтому всё это лежит только в `data/`, которая закрыта в `.gitignore`. Цитаты из диалогов в эталон не копируйте: для сравнения они не нужны.

## Состав эталона

15 диалогов: 6 RU, 4 EN, 3 KZ чата и 2 звонка. Список даёт техлид. Казахские диалоги проверяет человек, который читает по-казахски.

Размечается только работа оператора по правилам из чек-листа и его подсказок (`llm_hint`). Реплики бота и системы — контекст. Эталон не подгоняется под ответы модели: если разметку пришлось исправить, причина записывается в `note`.

## Формат `gold.json`

```json
{
  "dialogs": [
    {
      "conversation_id": "<id диалога>",
      "language": "RU",
      "channel": "agent chat",
      "checklist_version": 3,
      "criteria": {
        "c01": "yes",
        "c02": "na",
        "c03": {"answer": "na", "doubtful": true, "note": "клиент отказался от проверки"},
        "c04": 15,
        "c05": "yes",
        "c06": 10,
        "c07": "no",
        "c08": "no"
      }
    }
  ]
}
```

- Ответ: `"yes"`, `"no"`, `"na"` или число — ступень шкалы.
- Объект `{"answer": ..., "doubtful": true}` помечает спорный критерий. Так отмечаются случаи, где правило ещё не подтвердили организаторы, например c03 при отказе от проверки и c07 при звонке, оборванном клиентом.
- `"doubtful": true` на уровне диалога помечает спорными все его критерии, `"doubtful_criteria": ["c07"]` — отдельные.
- Необязательные поля: `total` и `gross_error`. Без них итог эталона считается тем же движком подсчёта, что и в приложении.
- `kz_checked_by` у казахских диалогов: кто и как проверил разметку, например «Карим, через переводчик». Отчёт показывает, сколько KZ-диалогов проверено и какие нет.
- `seen_model_before_labeling: true`: разметчик видел ответы модели до разметки. Отчёт перечисляет такие диалоги, чтобы их можно было переразметить вслепую.

## Запуск

Модель при сравнении не вызывается: берутся уже сохранённые оценки.

Из запущенного приложения, с сохранением выгрузки:

```powershell
python -m eval.compare --gold data/gold/gold.json --api http://127.0.0.1:8000 --save-model data/gold/model.json --json data/gold/report.json
```

Повторно, без приложения:

```powershell
python -m eval.compare --gold data/gold/gold.json --model data/gold/model.json
```

Из приложения берётся последняя оценка каждого диалога эталона, исходная, без решений по апелляциям. Если она сделана по чек-листу с другими критериями, отчёт об этом предупредит: такие диалоги нужно оценить заново по нужной версии.

## Что в отчёте

- Совпадение по критериям без спорных случаев.
- Спорные случаи отдельной строкой: расхождение в них не считается ошибкой модели.
- Грубая ошибка: совпал ли флаг.
- Итоговый балл: средняя и максимальная разница, сколько совпало точно.
- Разбивка по критериям, языкам и каналам.
- Виды расхождений:
  - в эталоне N/A, а модель ответила;
  - модель поставила N/A без причины;
  - другая ступень шкалы;
  - перепутаны да и нет;
  - нет результата модели.
- Список всех расхождений в виде «эталон → модель».
