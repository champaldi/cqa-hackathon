# CQA: оценка качества диалогов

Прототип Conversation Quality Analytics для хакатона Freedom Broker. Команда из 4 человек, 24 часа.

**Статус: этап планирования.** Приложения пока нет. В репозитории лежат план, стартовый чек-лист и черновик контракта данных.

## Что строим

Веб-приложение оценивает работу оператора по настраиваемому чек-листу и показывает баллы, объяснения и реплики-доказательства. Вторая часть: апелляция, решение проверяющего и пересчёт итога.

Предлагаемый стек:

- **Сервер:** Python, FastAPI, SQLite. Он же отдаёт интерфейс, поэтому CORS не мешает.
- **Интерфейс:** HTML, CSS и JS без сборки, так проще перенести в Dynamics 365.
- **Модель:** подключается через общий интерфейс. Есть режим-заглушка без ключа, чтобы интерфейс и тесты работали бесплатно.

## Как получить данные

Данные приходят из API организаторов и в репозиторий не попадают: часть диалогов реальная, а ссылка подписана.

1. Скопируйте `.env.example` в `.env`.
2. Вставьте в `CQA_DATASET_URL` адрес кнопки «Открыть GET для DEV» из PDF-гайда (стр. 3).

`.env`, `data/` и `*.pdf` закрыты в `.gitignore`. Не коммитьте их.

## Задачи и Pull Request

**Карим: Tech Lead / Backend**

1. `contract/skeleton`: каркас с заглушками, контракт и CI. После него начинают все.
    - Папки по таблице ролей, `contracts.py` берётся за основу.
    - Заглушки оценки, подсчёта баллов и хранилища: приложение запускается и проходит весь путь без ключа модели.
    - `AGENTS.md` и `CLAUDE.md` с правилами для нейронок.
    - CI: линтер, тесты и проверка, что PR меняет только файлы своей роли.
    - Защита `main`: только через PR с зелёным CI и одобрением.
2. `backend/data-and-storage`: SQLite, импорт по `group_id`, повторы запросов и локальный кеш, время реплик, ссылка на аудио.
3. `backend/batch-and-appeals`: пакетная оценка в фоне, повтор упавших диалогов, апелляции и решения.
4. `backend/control-ready`: новый `group_id` и загрузка файла через интерфейс, прогон всего набора.

**Алдияр: AI Engineer**

1. `llm/evaluator-core`: промпт собирается из чек-листа, ответ проверяется (шаг шкалы, допустимость N/A, цитата есть в реплике), при ошибке повтор.
2. `llm/languages-and-calls`: RU, KZ и EN, особенности звонков.
3. `llm/quality-and-cost`: сравнение моделей на эталоне и стоимость одной оценки со всеми вызовами.

**Максим: Frontend Engineer**

1. `ui/review-card`: список диалогов, карточка с транскриптом и баллами, переход к реплике.
2. `ui/audio-and-appeals`: плеер с переходом к фрагменту, подача апелляции, экран проверяющего, исходная и финальная оценка.
3. `ui/run-and-polish`: запуск пакетной оценки с прогрессом, состояния ошибок, подготовка к Dynamics 365.

**atomi7e: QA / Product Engineer**

1. `qa/scoring-engine`: веса, шкалы, перераспределение N/A, секции, округление, грубая ошибка отдельно, пересчёт после апелляции.
2. `qa/gold-set`: ручная разметка 15–20 диалогов на всех языках и сравнение с моделью.
3. `qa/checklist-editor`: редактор критериев, весов, типов ответа, N/A и шкал; сохранение новой версии.
4. `qa/readme-and-demo`: README с запуском, моделью и стоимостью, сценарий защиты на 5 минут, репетиции.

## Правила работы

**Чтобы код не ломался:**

1. В `main` попадает только PR с зелёным CI и одним одобрением.
2. Один PR — одна задача: 3–4 небольших на человека вместо одного огромного в конце.
3. PR стартует черновиком с тестами-спецификацией: сначала красные, к готовности зелёные.
4. CI проверяет, что PR меняет только файлы своей роли. Роль определяется по префиксу ветки.
5. Перед слиянием ветка обновляется от `main`.

**Чтобы нейронка не путалась:**

1. В корне будет `AGENTS.md` с описанием проекта, таблицей ролей и запретами. `CLAUDE.md` ссылается на него. Оба появятся в `contract/skeleton`.
2. Первым делом нейронка смотрит ветку, определяет роль и читает свою задачу.
3. Правит только свою зону. Если нужна чужая правка, пишет об этом в PR, а не делает сама.
4. Запреты для всех: не зашивать критерии в код, оценивать только оператора, не менять исходную оценку, не коммитить секреты и данные.
